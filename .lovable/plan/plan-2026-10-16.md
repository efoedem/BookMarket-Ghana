# Plan

Build the current admin page into a two-level admin system.

## What will change

- Make `edemofficial@gmail.com` the super admin.
- Add ownership to books so every uploaded book is tied to the admin who added it.
- Keep the super admin able to manage every school, department, book and order.
- Limit regular admins to:
  - only their uploaded books;
  - only orders containing their books;
  - a small dashboard showing their total paid orders and paid amount.
- Add an Admins view for the super admin showing each admin profile, books uploaded, paid orders and total paid amount.
- Add a form for the super admin to create or promote another admin by email, with optional name, phone, school and department.
- Add selectable paid-order rows and CSV/Excel downloads for selected people.
- Keep student browsing, cart, checkout, payment and receipts working as-is.

## Database updates

- Extend roles from `admin/student` to include `super_admin` while keeping `admin` working for existing checks.
- Add `uploaded_by` to books and backfill existing books to the super admin.
- Add safe helper functions for role and ownership checks.
- Update access policies so regular admins can manage only their own books while super admin can see everything.

## App updates

- Update admin server functions to return role-aware data.
- Add admin creation/promotion server function.
- Rework the admin page into dashboard, books, orders, and super-admin-only management views.
- Generate a fresh downloadable zip after the app is updated.

## Verification

- Check the latest build status after changes.
- Run targeted tests if existing tests cover routing or admin behavior.
- Package the updated source as a zip for download.
